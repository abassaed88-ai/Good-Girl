# معمارية التطبيق

## 1. مبدأ التشغيل دون إنترنت
تكون قاعدة البيانات المحلية على الجهاز هي مصدر الحقيقة للعمليات اليومية. لا تتطلب إضافة أو تعديل أو قراءة المبيعات والمشتريات والمخزون والحسابات اتصالاً بالشبكة.

## 2. التقنية المقترحة
- Android Native باستخدام Kotlin.
- Jetpack Compose للواجهات.
- Room / SQLite للتخزين المحلي والعلاقات والمعاملات.
- DataStore للإعدادات والتفضيلات.
- WorkManager لمهام المزامنة والنسخ الاحتياطي المؤجلة عند توفر الاتصال.
- طبقات واضحة: واجهة المستخدم، حالات الاستخدام، المستودعات، ومصادر البيانات.

هذه اختيارات تأسيسية قابلة للمراجعة عند إعداد ملفات البناء، وليست ادعاءً بأن التطبيق بُني أو اختُبر.

## 3. قواعد سلامة البيانات
- تنفيذ ترحيل كل عملية مالية مترابطة داخل معاملة قاعدة بيانات واحدة.
- حفظ تكلفة الوحدة وسعر البيع والخصومات والضرائب/الرسوم المطبقة وقت العملية كسجل تاريخي غير قابل للتغيير بتعديل بطاقة المنتج.
- عدم احتساب الربح مرتين عند ترحيل الفاتورة أو تسجيل التحصيل.
- فصل إجمالي الفاتورة عن المبلغ المقبوض والمتبقي والآجل.
- تسجيل حركات المخزون والمال والحسابات بمراجع تربطها بالمستند الأصلي.
- استخدام معرفات ثابتة للعمليات لدعم المزامنة ومنع التكرار لاحقاً.
- عدم حذف المستندات المالية المرحلة حذفاً نهائياً؛ تستخدم آلية إلغاء/عكس موثقة.

## 4. المزامنة والنسخ الاحتياطي
- لا تُفعّل المزامنة إلا عند وجود اتصال وموافقة المستخدم وإعداد مزود سحابي.
- تظل الكتابة المحلية متاحة أثناء انقطاع الاتصال.
- تحفظ تغييرات المزامنة في سجل عمليات/طابور محلي مع حالات واضحة.
- يجب التعامل مع إعادة المحاولة وتعارض التعديلات ومنع تكرار العمليات.
- النسخ الاحتياطي مشفر، مع التحقق من سلامة النسخة وإمكانية الاستعادة.
- صيغة النسخة الجديدة `.ggbackup`: تشفير AES-256-GCM مع وسم تحقق 128 بت، ومفتاح 256 بت مشتق من كلمة المرور باستخدام PBKDF2-HMAC-SHA256 بعدد 600,000 دورة، وملح عشوائي 16 بايت وNonce عشوائي 12 بايت لكل ملف.
- لا تُخزّن كلمة المرور داخل التطبيق أو النسخة؛ يجب أن يحتفظ المستخدم بها في مكان آمن منفصل، وفقدانها يمنع فك التشفير.
- يمكن استيراد ملفات JSON القديمة غير المشفرة للتوافق، وتظهر للمستخدم رسالة تحذير لتصدير نسخة مشفرة جديدة.
- يفحص التطبيق العلاقات والأرصدة قبل الاستعادة، ثم يستبدل سجلات قاعدة البيانات داخل معاملة ذرية؛ اختبار الاستعادة اليدوي على أجهزة حقيقية ما زال مطلوباً.
- لا يُختار مزود سحابي أو تُرسل بيانات إلى خدمة خارجية قبل تحديد الخدمة والحصول على موافقة المستخدم.

## 5. اتجاه الواجهات
- واجهات عربية RTL بالكامل.
- الأرقام المعروضة والمدخلة بصيغة 0123456789.
- لوحة ألوان: أزرق، رمادي فاتح، أبيض، أخضر فاتح، أحمر هادئ، بنفسجي.
- يمنع الأصفر والبرتقالي وكل درجاتهما.
- جداول واضحة، مسافات مريحة، أيقونات متناسقة، وحالات تحميل/فراغ/خطأ مفهومة.

## 6. العملة وأسعار الصرف
- دعم الليرة السورية والدولار الأمريكي.
- حفظ سعر الصرف وتاريخه ومصدر إدخاله.
- حفظ العملة وسعر الصرف المستخدمين وقت كل مستند؛ لا يعاد حساب المستندات التاريخية تلقائياً عند تغير السعر.
- التقارير تعرض بعملة محددة وفق قاعدة تحويل معلنة.

## 7. مراحل التحقق
1. تثبيت بنية Android والبناء الأولي.
2. تصميم مخطط قاعدة البيانات وترحيلاتها واختبارات العلاقات.
3. بناء نظام المنتجات والمخزون والمشتريات والمبيعات.
4. بناء الحسابات والديون والصندوق والتحصيلات.
5. بناء المصروفات والإيرادات والتقارير.
6. العملات وأسعار الصرف.
7. الطباعة وPDF والنسخ الاحتياطي.
8. اختبارات انقطاع الإنترنت، إغلاق التطبيق، إعادة التشغيل، وسلامة الأرصدة.
9. بناء APK والتحقق من تثبيته وتشغيله قبل تسليمه.

لا تعتبر أي ميزة مكتملة لمجرد وجود شاشة لها؛ يلزم اختبار سلوكها ونتائجها.
