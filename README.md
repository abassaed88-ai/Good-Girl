# Good Girl — تطبيق إدارة ومحاسبة المتجر

تطبيق Android باللغة العربية لإدارة المبيعات والمشتريات والمخزون والعملاء والموردين والحركة المالية. المشروع في مرحلة التطوير والتحقق، والنسخة الحالية **Debug** مخصصة للتجربة وليست إصدار نشر نهائياً.

## مبادئ المشروع

- **Offline-first:** تحفظ العمليات الأساسية محلياً باستخدام Room / SQLite، ولا تتطلب اتصالاً بالإنترنت.
- **العربية أولاً:** الواجهات عربية وباتجاه RTL.
- **الأرقام:** تستخدم الأرقام اللاتينية 0123456789 في المدخلات والتقارير والتواريخ.
- **العملات:** الليرة السورية SYP والدولار الأمريكي USD. تحفظ العملة وسعر الصرف المستخدم وقت المستند؛ تعرض التقارير العملات منفصلة ولا تجمعها أو تحولها تلقائياً.
- **الهوية البصرية المعتمدة:** الوضع الفاتح بخلفية أزرق جليدي #EAF6FA وبطاقات بيضاء #FFFFFF ولمسات تركوازية #18AFC3. الوضع الداكن بخلفية كحلية #071F36 وبطاقات #0E3554 ولمسات تركوازية #36BCE0. تُستخدم النصوص عالية التباين وفق الثيم المختار، مع تجنب الأصفر والبرتقالي تماماً.

## الوظائف المنفذة في النسخة التطويرية

- لوحة تحكم وروابط مستقلة للمبيعات اليومية، فواتير البيع، فواتير الشراء، المنتجات والمخزون، الحسابات، الصندوق، التقارير، النسخ الاحتياطي والإعدادات.
- إضافة المنتجات وتعديلها وأرشفتها، مع التصنيفات ووحدات القياس وأسعار الشراء والبيع.
- شاشة مستقلة لتحديد سعر البيع. تحديث السعر الحالي لا يغير كلفة الشراء أو المخزون أو أسعار فواتير البيع السابقة.
- صفحة المبيعات اليومية، وتعرض تفاصيل مبيعات اليوم وربح المواد المحسوب من كلفة الوحدة المحفوظة وقت البيع.
- فواتير بيع وشراء متعددة البنود، مع الخصومات والدفعات والمتبقي وتحديث المخزون والأرصدة ضمن معاملات قاعدة بيانات.
- استخدام متوسط تكلفة مرجح عند الشراء، وحفظ سعر الوحدة والكلفة والكمية بوحدة الأساس وسعر الصرف كلقطات تاريخية على بنود الفواتير.
- إدارة العملاء والموردين والأرصدة الافتتاحية وكشوف الحساب والتحصيلات والدفعات المستقلة، مع فصل حركة الصندوق عن مستحقات الأطراف.
- تسجيل الإيرادات والمصروفات وحركات الصندوق.
- تقارير مالية حسب اليوم أو الشهر أو كامل المدة، وتحليل ربحية المواد مع إبقاء العملات منفصلة. أضيفت أيضاً قائمة دخل وميزانية عمومية محسوبتان من قيود دفتر اليومية العام، مع فصل العملات وعدم إجراء تحويل تلقائي.
- تصدير فواتير البيع والشراء والتقارير المالية وكشوف حساب العملاء والموردين إلى PDF باللغة العربية.
- حفظ سجل محدود لأسعار الصرف واستخدام السعر المحفوظ كقيمة افتراضية للمستندات الجديدة، من دون إعادة تسعير المستندات السابقة.
- دفتر يومية عام مزدوج القيد، ودليل حسابات، وميزان مراجعة وكشوف أستاذ، مع قيود مرتبطة بمصادر العمليات.
- قائمة دخل وميزانية عمومية من دفتر الأستاذ العام، مع فصل العملات وإظهار الأرباح غير المقفلة والأرباح المرحلة من قيود الإقفال.
- قائمة تدفقات نقدية مباشرة من حركات حساب الصندوق في دفتر الأستاذ، تفصل المقبوضات والمدفوعات حسب مصادر التشغيل المعروفة، وتُظهر القيود النقدية غير المصنفة بدلاً من افتراض تصنيفها.
- لا تعيد القوائم المالية بناء النشاط التاريخي قبل ترقية قاعدة البيانات؛ تبدأ التغطية المحاسبية من الأرصدة الافتتاحية المرحّلة، وتُظهر قائمة التدفقات النقدية هذا الحد التاريخي بوضوح.
- نسخ احتياطية محلية مشفرة بصيغة .ggbackup باستخدام AES-256-GCM ومفتاح مشتق من كلمة مرور المستخدم عبر PBKDF2-HMAC-SHA256 بعدد 600,000 دورة، مع ملح وNonce عشوائيين لكل نسخة.
- دعم استيراد ملفات JSON القديمة غير المشفرة مع تحذير، والتحقق من هوية النسخة وسلامة السجلات قبل الاستعادة الذرية.
- اختبارات وحدات واختبارات Android تكاملية على قاعدة Room ومحاكي Android.
- إغلاق فترة محاسبية بعملة ونطاق تاريخ محددين، مع معاينة صافي الربح أو الخسارة، وقيد إقفال مزدوج متوازن إلى حساب أرباح محتجزة مستقل عن رأس المال. يمنع النظام إغلاق الفترات المتداخلة أو ترحيل حركات بتاريخ داخل فترة مغلقة.

## ما يزال قيد التطوير قبل اعتماد النظام محاسبياً

- استكمال إجراءات العكس والتدقيق للمستندات الآلية، وتوفير مسار مدقق لإعادة فتح فترة مغلقة عند الحاجة. قيد الإقفال المنشور لا يملك حالياً إجراء تراجع من الواجهة.
- إعادة تقييم فروقات العملة وفق سياسة عملة وظيفية واضحة. أصبحت القيود اليدوية تدعم تصنيف حركات الصندوق اختيارياً إلى تشغيلية أو استثمارية أو تمويلية، مع الحفاظ على التصنيف عند إنشاء القيد العكسي.
- القوائم الجديدة من دفتر الأستاذ لا تعيد بناء الأرباح التاريخية قبل ترقية قاعدة البيانات؛ فقد رُحّلت الأرصدة القديمة كقيود افتتاحية مجمعة. يبقى تقرير الفواتير التاريخي وتحليل المواد منفصلين.
- تصدير قائمة الدخل والميزانية وميزان المراجعة وكشف الأستاذ إلى PDF والطباعة المباشرة/الحرارية.
- سياسة تحويل عملات واضحة وتقارير موحدة اختيارية تعتمد سعر صرف محدداً وتوثق فروقات العملة؛ لا يجوز جمع أرصدة SYP وUSD كما لو كانت عملة واحدة.
- استكمال الطباعة المباشرة وقوالب الطباعة الحرارية؛ تصدير PDF الأساسي موجود.
- اختبار التصدير والاستعادة يدوياً على أجهزة Android فعلية، واختبار دورة الاستخدام اليومية بعد إغلاق التطبيق وإعادة تشغيله.
- إعداد نسخة Release بتوقيع إنتاجي وإجراء اختبار قبول نهائي قبل النشر.

## البناء والاختبارات

يستخدم المستودع GitHub Actions لتنفيذ:
1. توليد مخططات Room والتحقق منها.
2. اختبارات الوحدة.
3. اختبارات Android التكاملية عبر connectedDebugAndroidTest على محاكي Android.
4. بناء app-debug.apk ورفعه كـ Artifact.

لا تعتبر الميزة مكتملة لمجرد وجود شاشة لها؛ يجب اختبار أثرها على قاعدة البيانات والتقارير والسجلات التاريخية. ولا تُقدّم نسخة Debug على أنها إصدار Release أو نسخة جاهزة للنشر.


## متطلبات التخصيص والتجهيز التجاري المستقبلية

هذه متطلبات معتمدة للتصميم المعماري، وليست وظائف منفذة حالياً:
- استكمال تدقيق جميع الشاشات الفرعية والجداول للتأكد من استخدام ألوان الثيم الفاتح/الداكن المعتمدة دون بقاء خلفيات ثابتة قد تكسر التباين؛ خيار الألوان الإضافية مؤجل ولا يغيّر الهوية الأساسية المعتمدة.
- دعم أحجام الخطوط وتخصيص العناوين الظاهرة للمستخدم دون تغيير مفاتيح التنقل أو رموز الحسابات أو معنى القيود المحاسبية.
- حفظ تفضيلات المظهر والاختصارات الظاهرة في لوحة التحكم لكل مستخدم.
- عزل بيانات كل متجر/عميل ونسخه الاحتياطية قبل توزيع نسخ تجارية متعددة.
- تجهيز واجهة داخلية لنظام تراخيص موقعة رقمياً والتحقق منها محلياً؛ تؤجل خدمة التراخيص السحابية ولوحة الإدارة حتى استقرار المحاسبة.
- يبقى تسجيل وقراءة العمليات المحاسبية الأساسية متاحاً دون إنترنت، ولا يجوز أن يؤدي تعذر التحقق من الترخيص إلى حذف بيانات العميل أو إخفائها.
